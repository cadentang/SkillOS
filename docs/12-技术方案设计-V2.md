### 2.2 技术决策表（V2-T1 ~ V2-T10）

| # | 决策 | 理由 / 对齐 |
|---|---|---|
| **V2-T1** | 设备侧开关存储：新表 `app_settings(key TEXT PK, value JSON, updated_at)`，本地 + 云端同构 | 现状无 settings 存储（Settings 页只读探测 + cloud_repo 写 custom Runtime）。SQLite/PG 同构表比 JSON 文件可审计、可迁移；遥测开关属设备本地域，云端同表不同 key 域，不混用 |
| **V2-T2** | L1 采集点收口在 `usage_service.record()` 单一入口；engine / MCP server / WS 处理器 / CLI 服务层只调它 | 采集定义唯一化（N-01.1 / N-11.2 同源）；避免 `engine.py` 继续膨胀；`usage_collect_enabled=false` 时 record() 直接 return（零开销路径） |
| **V2-T3** | token 归属算法 = 纯函数 `attribute_tokens(events, usage_slices) -> Attribution`，进 `core/algorithm/telemetry.py` | 与 `summarize_health` 同风格：输入输出都是数据，可单测幂等（E-01.4 思路复用）；daemon/API/CLI 三条路径共用 |
| **V2-T4** | 自定义规则执行模型：声明式 YAML → 匹配动作仅 `re.search`（预编译）；超时用 **ThreadPoolExecutor + future.result(timeout=0.1)** | `signal.alarm` Windows 不可用（跨平台 P0）；线程池超时虽不能强杀正则，但 check 流程可超时中断该条并记 warn（N-03.3 语义满足；真实 ReDoS 风险由 RK-V2-03 的条数上限 + 保守 pattern 审查兜底） |
| **V2-T5** | `ruleset_hash` = `sha256(sorted(规则文件相对路径 + 文件字节))` 聚合 | 与 `hash_bytes` 字节级口径一致（T16）；排序保证同内容不同顺序文件集合哈希稳定 |
| **V2-T6** | CR 状态机 = 代码内显式迁移表 `{(from, event): to}` + 单点 `transition()` + DB CHECK 约束兜底 | 状态非法迁移双层拦截（应用层 ValueError + DB 层 IntegrityError）；终态回跳天然被拒（E-05.1） |
| **V2-T7** | L2 适配器 = **YAML 声明式解析配置**（glob 模式 / 行 JSON 字段映射 / skill 关联规则），适配器注册表按 runtime key 索引 | 路径即数据：加 Runtime = 加一份 yaml，不加代码（N-11.5）；与 `builtin_potential_runtimes.yaml` 既有模式同构 |
| **V2-T8** | 定时任务调度：daemon 现有 asyncio 事件循环上加最小调度器（`asyncio` task + 间隔计算），不引入 APScheduler / celery | 单人项目零新依赖（02 §9 纪律）；3 个任务都是轻量周期活 |
| **V2-T9** | 云端聚合 upsert：`INSERT ... ON CONFLICT(device_id, skill_id, date, via) DO UPDATE SET count = count + excluded.count` | SQLite ≥3.24 与 PG 12+ 语法同构（NFR-V2-06）；补报去重在冲突键上天然完成（N-01.9） |
| **V2-T10** | 大文件安全扫描（N-08.3 例外）：扫描器对 `in_git=false` 文件**流式分块读取**（8KB 块 + 跨块正则拼接缓冲），只读匹配不进哈希 | 避免把超 5MB 文件整读进内存；"参与扫描不参与哈希"两条路径物理分离，防止误改 T2 判定 |

### 4.2 E-02 折旧判定（本期核心新算法）

新建 `core/algorithm/decay.py`，纯函数：

```python
def evaluate_decay(
    *, days_since_last_commit: int | None,          # None => unknown（不猜，NFR-10.4）
    inbound_refs: int,                              # skill_dependencies 反向入度 + 相对路径引用命中
    declared_deps: list[str] | FormatUnknown,       # 解析失败 => FormatUnknown（E-02.4）
    resolved_slugs: set[str],                       # 库内实际存在的 slug 集
    dependency_bindings_ok: dict[str, bool],        # 每个 slug 在本 skill binding 所在 Runtime 是否有有效 binding
    upstream_status: str | None,                    # E-08 未启用恒 None
) -> DecayResult           # {staleness, dependency_broken, upstream_divergence, value: dict}
```

实现要点：

1. **staleness**（E-02.1/2）：`days_since_last_commit=None → unknown`；阈值 `STALENESS_DEGRADED_DAYS = 90`，`inbound_refs >= 1` 放宽至 `STALENESS_DEGRADED_DAYS_RELAXED = 180`，命中放宽时 `value.relaxed_by_refs = true`；
2. **dependency_broken**（E-02.3/4）：两层判定照抄需求（库内缺 slug → degraded；库内有但 binding 不覆盖 → degraded）；frontmatter `dependencies` 非 list / 元素非 str → `unknown` 并返回 gate info 信号 `fm.dependencies.format`（由 check_service 转为 info finding）；
3. **upstream_divergence**（E-02.5）：`upstream_status is None → unknown`；E-08 启用后按 E-08.3 映射；
4. **days_since 输入源**：canonical 该 skill 目录最近 commit 的 UTC 时间，经既有 git 白名单 `version_log` 路径取（不读 `updated_at`，E-02.7 / T16）；时钟回拨 `days_since < 0` → 按 0 + warning 日志；
5. **引用计数**：`inbound_refs` 计算放 `services/usage_service.py` 同级新私有函数（查 `skill_dependencies` 反向入度 + 对库内其他 skill 正文做相对路径正则命中，正则 = `SKILL.md` 引用形如 `../<slug>/` 或 `skills/<slug>/`），**缓存于本次 check 会话内**（O(n) 预扫描一次，避免每 skill 全库重扫）；
6. **落库**（E-02.6）：走既有 `decay` WS op → `skill_checks(scope=decay)`，`value` 存完整原始测量值 JSON。

## 五、M2 遥测闭环：N-01 / N-02 / N-11 技术设计

### 5.1 L1 采集（N-01.1/2 + N-11.2）

**唯一入口** `usage_service.record(skill_id, op, via, *, duration_ms=None, ok=True, session_id=None, param_digest=None)`：

| 采集点 | via | 挂钩位置 | 说明 |
|---|---|---|---|
| MCP 工具入口 | `mcp` | `mcp/server.py` 各工具 handler 收口处 | `get_skill` / `status`(单 skill) / `sync_push` / `sync_pull`（N-01.1 ①） |
| WS 任务处理 | `web` | `api/ws_hub.py` 任务完成后回调 | `file_read` / `file_write`(带 skill 归属) / `push` / `pull` / `resolve_conflict` |
| CLI 服务层 | `cli` | `cli` 命令调用 service 后 | `status`(单 skill) / `log` / `push` / `pull` |
| daemon 内部 | `daemon` | 引擎内部动作（scan 后的 auto 动作等） | 仅统计，可不计入 via 维度展示 |

要点：

- **session_id 生成**：MCP / WS 每连接生成 UUID；CLI 单次进程即一个 session（跨进程会话聚合交给 L2）；
- **双写**：事件表插入（30 天滚动，**事实源**）+ 进程内聚合缓冲（仅作加速，见 `usage_aggregate` 任务）；`skill_usage_daily` 以**事件表为源**定时重算（TQ-02 已拍板 2026-10-24：幂等 upsert 重算当日行，崩溃零丢失，不依赖缓冲 flush）；
- **开关路径**：`usage_collect_enabled=false` 时 `record()` 读缓存的开关值直接 return（每 30s 刷新一次开关缓存，避免每事件查库）；
- Dashboard 浏览 / 全库 scan 不挂钩（N-01.1 排除项）。

### 5.2 日终聚合与清理（daemon 定时，V2-T8）

daemon 调度器（最小实现：asyncio task，每分钟检查一次到期任务表）注册 3 个任务：

| 任务 | 周期 | 动作 |
|---|---|---|
| `usage_aggregate` | 每日 00:10 本地时 | **以事件表为源重算**近 30 天聚合行（幂等 upsert，TQ-02 决议）；删除 `skill_usage_events` 中 30 天前行（清理只在重算完成后执行） |
| `report_generate` | 按 `report.cadence` | 调 `report_service.generate()`（N-02） |
| `upstream_check` | 每日一次（E-08.1） | 遍历 `upstream_sources`，锁外网络 + 落库（T17） |

### 5.3 云端上报（N-01.4/5/9）

- WS op 白名单 `WS_TASK_OPS` 增 `usage_report`（构造期校验 + 运行期双保险模式照抄 `logs` op）；
- 报文 = 聚合行数组（skill 标识 + 计数 + 日期 + via + N-11.6 聚合列），**无事件行、无 param_digest、无路径**；
- 客户端：`usage_report_enabled=false` 时**不构造任务**（零上报可测试断言：`test_usage_privacy.py` 打开 mock 云端断言无连接写出）；开启后每日一次，失败保留待报集合，重连后按日补报（N-01.9）；
- 服务端（cloud_repo）：V2-T9 upsert 合并；团队视图查询 = `SELECT skill_id, SUM(count) ... GROUP BY skill_id`（只见聚合，N-01.6）；
- 僵尸新口径（N-01.7）实现为 `usage_service.zombie_slugs(days=STALENESS_DEGRADED_DAYS)`：`近 90 天 SUM(count)==0` ∩ `decay staleness==degraded`，管理者视图唯一调用此函数（口径单点）。

### 5.4 L2 Runtime 会话适配器（N-11.4/5/9）

**解析配置**（V2-T7，`core/algorithm/adapters/telemetry/claude-code.yaml`，示意）：

```yaml
runtime: claude-code
autodetect:                            # 手动路径存在时整段跳过（N-11.9③）
  - "{home}/.claude/projects"
session_glob: "**/*.jsonl"
usage_field_map:                       # 行 JSON → 归属器输入
  event_type: "type"                   # 判定该行是否 usage 行
  input_tokens: "message.usage.input_tokens"
  output_tokens: "message.usage.output_tokens"
  cache_read: "message.usage.cache_read_input_tokens"
  timestamp: "timestamp"
skill_match:                           # 会话行 → skill 关联（N-11.4）
  - scan_fields: ["message.content", "toolCall.parameters"]
    pattern: "({deploy_roots}/(?P<slug>[A-Za-z0-9-]+))|(skills/(?P<slug>[A-Za-z0-9-]+)/)"
```

**import 编排**（`telemetry_service.import_runtime(runtime_key)`）：

```
1. 取路径集：app_settings["telemetry.runtime_paths"][key] 非空 → 用之（跳过 autodetect）
                                        否则 → 适配器 autodetect 展开
2. 路径集为空或全部不可达 → 抛 TelemetryPathError（附尝试清单 + 手动指定提示），不产空聚合（N-11.9④）
3. 逐文件流式解析（逐行 json.loads；损坏行 skip 计数，N-11.8）
4. 抽取 usage 切片 + skill 命中（扫描内容仅内存匹配，不落盘正文）
5. 调 algorithm/telemetry.attribute_tokens() 时间片归属（N-11.3 纯函数）
6. 去重：文件路径 + 行号哈希入 seen 集合（多路径合并同一 session 文件只计一次，N-11.9⑤ GWT）
7. 合并写入 skill_usage_daily（增量列）+ 事件表补 skill 级 token 记录
```

**CLI**：`skillos telemetry import claude-code`、`telemetry path set/show/clear`（读写 `app_settings["telemetry.runtime_paths"]`）。Web 设置页表单等价写同一 key。

## 六、M3 治理扩展：N-03 / N-08 / E-04 技术设计

### 6.1 规则引擎（N-03）

`core/algorithm/rule_engine.py`：

```python
@dataclass(frozen=True)
class CustomRule:
    rule_id: str          # 必须 "custom." 前缀（加载期校验，冲突显式报错 N-03.2）
    level: str            # error / warn / info
    target: str           # description / frontmatter / file_content / file_list
    pattern: re.Pattern   # 加载期编译，编译失败 → 该规则 invalid（info finding，N-03.4）
    flags: frozenset[str]
    scope_paths: tuple[str, ...] | None
    scope_exclude: tuple[str, ...] | None
    message: str

def load_rules(rules_dir: Path) -> tuple[list[CustomRule], list[InvalidRule]]: ...
def run_custom_rules(rules, snapshot, *, timeout_s=0.1) -> list[RuleFinding]: ...
```

- **target 分派**：`description/frontmatter` 单次取值匹配；`file_content` 逐文件（ respects `scope` + N-08.3 大文件流式例外）；`file_list` 对路径列表匹配；
- **架构断言**（N-03.6 / NFR-V2-05）：引擎模块**不 import** `eval` / `exec` / `importlib`（CI 静态扫描测试断言 import 白名单）；测试注入含 `__import__` 的规则文件断言原样作为文本匹配不执行；
- **限额**：`MAX_CUSTOM_RULES = 200`（加载期超限显式报错）；单条匹配超时（V2-T4 线程池 100ms）→ warn finding「正则超时」不中断（N-03.3）；
- `ruleset_hash`（V2-T5）由 `rule_service.ruleset_hash(rules_dir)` 计算，check 时写 `skill_checks.ruleset_hash`（revision ③）；
- **ignore 白名单**（N-08.2）：`rule_service.load_ignores()` 读 `.skillos/rules/ignore.yaml`（`rule_id + path 模式 + 理由`），命中过滤，ignore 记录本身以 info 级落 `skill_checks`（可审计）。

### 6.2 安全扫描规则集（N-08）

- 预置规则 = 随包附带文件 `skillos/core/algorithm/adapters/rules/security.yaml`（约 10 条，类别/级别照 `docs/11` §8.4 表），首启时**拷贝**到用户仓库 `.skillos/rules/`（git 版本化、用户可改可删，N-08.1）——拷贝而非引用，保证规则与用户仓库同源演进；
- check 流程追加顺序：内置 11 条 → custom（含 security）→ ignore 过滤 → 落库；`check --security-only` CLI 入口过滤 `category: security`（N-08.5，CI 用）；
- **规则文件版本随包**：版本号写文件头 `# ruleset-version: 1`，升级包时用户文件不自动覆盖（保留用户改动），新增规则以新文件 `security-2.yaml` 追加。

### 6.3 相似检测启用（E-04）

- `similarity.py::find_similar` 已有，补：触发时机挂钩（**独立于 check 性能基准**——check 尾部异步触发 + 详情页手动「立即比对」按钮，不计入 NFR-V2-01 的 10s 口径，TQ-03 已拍板 2026-10-24）；增量 = 新/变更 skill vs 全库；结果落 `skill_similarity`（表已存在，无迁移）；幂等 = 同输入不新增行（GWT：upsert by (a, b)）；正文截断 5000 tokens 常量；
- O(n²) 边界照 `docs/11` E-04.4：>500 skill 非目标，不写代码。

### 7.1 CR 状态机（E-05）

`cr_service.py` 从 8 行薄壳重写为完整服务（允许：现状即欠账，需求文档 E-05 已立）：

```python
TRANSITIONS = {
    ("open", "approve"):  "approved",
    ("open", "reject"):   "rejected",
    ("open", "close"):    "closed",
    ("approved", "merge"): "merged",
    ("approved", "close"): "closed",
}   # 终态无出边 → 回跳天然拒绝（E-05.1）

def transition(cr, event, actor) -> CrResult:
    # 1. 角色校验：approve/reject 需 owner/member（viewer → 403 FORBIDDEN）
    # 2. reject 必须带理由 → 落 cr_comments
    # 3. merge 前置：对 CR 目标快照跑 run_gate（与 push 前置同一实现，NFR-10.5）
    #    has_error → 拒绝迁移，CR 留 open，GATE_FAILED 明细写 cr_comments
    # 4. merge 时 base_hash 比对 canonical，不匹配 → 409 STALE（E-05.3）
    # 5. 迁移落库 + 审计（复用不可变审计通道）+ WS 事件 cr.updated（E-05.4）
```

- 合并动作 = canonical commit（走既有 git 具名路径，E-05.5）；指向 skill 已删除 → 同步时批量 `close` + 系统评论（E-05.6，挂 daemon scan 后钩子）；
- **API**：`POST /api/change-requests/{id}/review`（body: action=approve/reject + reason）、`POST /api/change-requests/{id}/merge`；均走 `{ok,data,error}` 包装 + base_hash 语义（merge 请求带提交时的 canonical hash）。
