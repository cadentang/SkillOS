## 0. 产品定义

**一句话定位（形态）**

> Skill OS —— **Agent 能力治理的控制台**。
> 浏览器里看清所有 Agent 各自装了什么、**谁改的**、**过没过检查**。

**一句话定位（能力）**

> **Skill 不只是分发 —— 还要能被验证。**
> 分发 + 漂移检测 + **质量检查** + **评测回归**。

**技术定义**

> Skill 的 canonical 仓库 + 跨 Runtime 适配层 + 漂移感知 + 版本可追溯 + 可被 Agent 自管 + **稳定身份与溯源** + **健康度与折旧度量** + **质量门禁**。

**叙事重心（v1.4 调整，源自 `06` §6.3）**

旧叙事"**写一次，四个 Agent 都能用**"这个位置**已经有成熟产品占位**（skills-manager，5532★、54 个 Agent、两年迭代、软链/拷贝双模式）。在"技术创新 + 商业价值"维度上继续讲"跨 Agent 分发 Skill"，评委会问"这跟它有什么区别"。

新叙事**从"分发"移到"治理与质量"** —— 因为**质量检查与评测是对方唯一的功能空白**，且恰好与本项目"AI 测试架构师"主线同源。

> **口径澄清（必须守住，否则会与 `OUT-2` 冲突）**
>
> | 表述 | 本期含义 | 状态 |
> |---|---|---|
> | **质量检查 / 门禁回归** | 规则集每次改动后重跑，结果落库、可对比历史（`FR-1.0.11` / `NFR-10.1`）—— **静态分析** | ✅ 做 |
> | **评测回归** | 叙事上指"**每次改完都要过一遍检查，指标不许退化**"；本期即门禁回归 | ✅ 做（口径见上） |
> | **运行时评测 / 跑分** | 真跑 Agent 执行任务并打分（Agent Evaluation）—— **动态评测** | ❌ `OUT-2`，V2 |

> **一句话记法**：**折旧是「静下来看」，跑分是「跑起来测」。** 前者本期做满，后者本期不做。

**产品能力分四层**（论证见 `08-战略定位.md` §3）

| 层 | 内容 | 本期 |
|---|---|---|
| 第 1 层 · 装得上 | 安装 / 分发 / 多端同步 | ✅ 已实现 |
| 第 2 层 · 数得清 | 跨端清单 / 漂移告警 / 版本账本 | ✅ 本期主体 |
| 第 3 层 · 说得清 | 稳定身份 / 溯源（谁改的） | ✅ 最小版进 Demo（决策 Q2） |
| 第 4 层 · 用得住 | 质量门禁 / 折旧 / 健康度 | ✅ 静态部分并入主线（决策 Q3） |

> **第 1~2 层是包管理器，第 3~4 层才是资产管理。** 本期做满第 1~3 层，第 4 层只做**静态分析**部分 —— 边界见 `OUT-2`。

**三级演进叙事**

| 层级 | 形态 | 商业价值 | 主要读者 |
|---|---|---|---|
| L1 个人 | 单机 Skill 库、多端分发、版本回滚、溯源 | 已实现，赛后即自用 | 写 Skill 的人 |
| L2 团队 | 共享 Skill 库、变更审查、权限、管理者视图 | 团队内 Agent 能力复用与合规 | **决策者（不写 Skill 的人）** |
| L3 企业 | Skill 准入、安全扫描、审计、交付 | 企业 AI 能力治理（FDE 场景） | 治理与合规 |

> 本期实现 L1 全部、L2 部分（协作模块 + 管理者视图最小版），L3 仅叙事。
>
> **个人侧是产品，公司侧是生意** —— 两者共用同一套能力，但**不共用同一套措辞**：对个人说"你的 Skill 库"，对公司说"团队的 AI 能力账本"（`08` §4 / §6）。

## 1. 交付物总览

**本产品由 3 个交付物构成。**

| ID | 交付物 | 形态 | 运行位置 | 包含 |
|---|---|---|---|---|
| **D1** | `skillos` 本地包 | Python 包（pipx 安装） | 用户机器 | 核心引擎 + CLI + daemon + MCP 三种模式 |
| **D2** | Web 控制台 | React SPA | 浏览器 | 3 个页面 |
| **D3** | 云端后端 | 容器服务 | 云 | HTTP API + WS Hub + Postgres + 沙盒变体 |

**D1 的三种运行模式不是三个产品**，共用同一引擎与编排层：

| 模式 | 命令 | 生命周期 | 面向 |
|---|---|---|---|
| CLI | `skillos <cmd>` | 一次性 | 用户终端 |
| daemon | `skillos daemon` | 常驻 | 云端调用 |
| MCP | `skillos mcp` | stdio | Claude Code / Codex |

**不单独交付**：`core` 引擎（D1 内部库）。

## 2. 交付物 D1：`skillos` 本地包

### 2.0 核心引擎（三种模式共用）

| ID | 需求 | 阶段 |
|---|---|---|
| FR-1.0.1 | 扫描 Runtime 目录树，识别 Skill 包边界（含项目级目录）。**Skill 检测规范**：`SKILL.md`（大写）是**唯一 canonical 标记**；`skill.md`（全小写）作 **legacy 兼容**识别，但不作为新建标准；**`README.md` / `CLAUDE.md` 绝不算 Skill 标记** —— 递归扫描时分类目录（如 `skills/research/`）里的 README 会被误判成 Skill，而**父目录一旦误判，其下的真 Skill 会被短路跳过**（依据 `06` A2） | P1 |
| FR-1.0.2 | 解析 `SKILL.md` frontmatter、文件树，以及 sidecar（如 `agents/openai.yaml`） | P1 |
| FR-1.0.3 | 识别嵌套子 Skill（`subskills/<name>/SKILL.md`） | P1 |
| FR-1.0.4 | 维护本地索引（SQLite），可随时从仓库重建 | P1 |
| FR-1.0.5 | **内容哈希（两级口径）**：① `hash_bytes` = `sha256(path + "\0" + sha256(content))` 排序聚合，**字节级、是存储身份，不做任何归一化**；② 换行归一化（`\r\n` → `\n`）是**独立的第二级比较**，只在字节 hash 已不等时调用 —— **不作废已存 hash、无需迁移**；不可读文件 / 非法 UTF-8 一律**按字节严格比较，不得假定相同**。**枚举函数只有一份**（`scan` / `hash` / `diff` / removals 守卫共用），排除集分三类定义：**① 影响 hash**（必须含 `__pycache__/`、`*.pyc`、`.DS_Store`、`.git/`、`.skillos/`）/ **② 只影响兜底比较**（行尾、BOM）/ **③ 纯噪音**（日志、临时文件）。**第二级折叠的三条边界**：只折叠**文本**、**孤立 `\r` 不动**（可能是脚本里的有意义字节）、**二进制一律不折叠**。依据 `07` D6 / `06` A3 / `06` B1 | P1 |
| FR-1.0.6 | 漂移检测，**7 态**：`SYNCED` / `MISSING` / `OUTDATED` / `MODIFIED` / `CONFLICT` / `UNMANAGED` / `ORPHANED`（语义与判定见下）。**判定第一判据只能是「内容 hash 不等」**；`mtime` 仅在内容已确定不同之后用于提示方向，**禁止读取 `updated_at` 之类的数据库列参与新鲜度判定**（依据 `07` D2）。**漂移必须按 Skill 聚合展示，组内取最严重状态**，不得把 N 个副本列成 N 行（依据 `07` N10） | P1（CONFLICT 于 P3） |
| FR-1.0.7 | 三方合并：**base = `render(canonical@installed_commit, installed_adapter_version)`**，local = 磁盘现状，remote = `render(canonical@HEAD, 当前 adapter_version)`；**base 与 remote 必须使用同一 adapter 版本**，否则 adapter 差异会被误判为内容冲突；本期只做整文件粒度 | P3 |
| FR-1.0.8 | Adapter 渲染：canonical → 目标 Runtime 的目录结构与 frontmatter 字段策略。**`render()` 必须是纯函数**（同 canonical + 同 adapter 版本 ⇒ 同字节输出），这是 base 可精确重建的前提。**渲染能力与路径一样是数据**：每个 Runtime 还须声明 `recursive_scan`（是否递归子目录）与 `category`（分类，用于分组展示）；**项目级路径必须为相对路径且不得含 `..`**；**用户可新增自定义 Runtime**（`custom:` 命名空间）并覆盖内置定义（依据 `06` A1 / B5） | P1 |
| FR-1.0.9 | 分发：原子写入 + 分发前备份 + 失败回滚 + **归属与删除守卫（FR-1.0.26）+ 部署自证（FR-1.0.27）+ 多目标整体拒绝（FR-1.0.28）** | P1 |
| FR-1.0.10 | 版本管理：封装 git（init / commit / log / show / **snapshot_at** / diff / rollback），**不自研 VCS、不暴露任意 git 命令与参数**。`init` 必须**显式指定传统 ref 格式与初始分支**（不吃 `init.defaultBranch` / `init.defaultRefFormat` 等用户全局配置，否则新库可能建成上层读不了的格式）；**锁文件不得放在会被克隆或整体替换的目录内**；`rollback` **前必须自动快照当前状态**，该快照用户可见、可再回滚。依据 `07` G1 / G2 / G6 / N23 | P1 |
| FR-1.0.11 | **质量门禁**：规则集分三级（`error` / `warn` / `info`）；**`error` 级在 `push` 前必须拦截**，除非显式传 `--allow-gate-failure`（该开关**不得出现在 MCP 路径**，见 `FR-1.3.6`）。规则清单与分级见 `04` §2.1.4 | P1 骨架 / P3 门禁 |
| FR-1.0.12 | 相似 / 重复 Skill 检测 | P3 |
| FR-1.0.13 | 上游来源跟踪与更新检测。**来源信息的唯一权威在 `upstream_sources`**，`skills` 上只保留 `source_kind` | P7 |
| FR-1.0.14 | **路径安全校验**：所有外部传入的 `path` 必须 `resolve()` 后仍落在 `root` 内，越界一律拒绝并返回 `PATH_TRAVERSAL` | P1 |
| FR-1.0.15 | **分发残留自检与恢复**：启动及 `doctor` 时扫描 Runtime 目录下的 `*.old` / `*.tmp-*` 残留，自动回滚到一致状态 | P1 |
| FR-1.0.16 | **同名 Skill 合并纳管**：同一 slug 出现在多个 Runtime 时默认合并为一条记录并挂多个 binding；仅当各副本**内容不一致**时才报冲突，由用户选主副本 | P1 |
| FR-1.0.17 | **全局写锁**：CLI / daemon / MCP 三个入口共用同一把跨平台文件锁，任一时刻只允许一个写入者。**网络 I/O 永不在锁内**（锁只覆盖"读写 repo 与 bindings"的那一小段，解析与预取在锁外完成）；**禁止在持锁期间做 `fsync` / 全量目录 rename / 目录 mtime 更新**。锁要求必须写进函数契约，不靠自觉。**前后台语义分级**：后台任务（daemon 批量 push）可能持锁 10–15s，**前台交互必须等待而不是立即失败**（建议等待上限 20s，超时才报 `BUSY`）；**Windows 的 `LockFileEx` 冲突返回 `ERROR_LOCK_VIOLATION` 而非 `WouldBlock`** → 抢锁失败必须按"**任何错误都重试**"实现，**不得按错误类型分支**。依据 `07` D5 / N18 / M4 / `06` A6 | P1 |
| FR-1.0.18 | **binding 基线字段**：`runtime_bindings` 必须记录 `installed_commit`（安装时的 canonical commit）与 `adapter_version`；`installed_version` **降级为展示字段，不作任何基线**（版本号 ≠ commit） | P1 |
| FR-1.0.19 | **渲染器版本漂移独立上报**：当前 adapter 版本与 binding 记录的 `adapter_version` 不一致时，置 `adapter_outdated` 标志（UI 显示「模板已升级」徽标）。**该标志为独立维度，不参与 `CONFLICT` 判定**，也不进入状态枚举 | P3 |
| FR-1.0.20 | **未纳管资产策略**：单文件 > 阈值（默认 5MB，可配）不入 git 且不参与漂移哈希；**含此类文件的 Skill 不得上报 `SYNCED`**，改为上报 `SYNCED*` 并附「含未纳管资产」徽标 —— 宁可不支持，不可检测不准。**判定粒度与聚合粒度分离**：判定以**单文件**为单位（比"整个技能"更精确 —— 同一 Skill 内的小文件仍照常纳管），聚合以 **Skill** 为单位标注（`has_untracked_assets`）—— **不撒谎靠的是"聚合标注 + 状态降级"，不是把判定粒度放粗**（依据 `06` A5） | P1 |
| FR-1.0.21 | **Skill 稳定身份**：`skill_id` 跨 Runtime / 跨机器 / 跨改名保持稳定。身份判定**分层进行**：`source_ref` → **唯一内容哈希** → `dir/name`；**任一层出现多个候选时必须不认**（宁缺勿滥），**禁止按相似度取最高分** —— 并列时的任意选择会让副本绑到错误的 Skill 上，而"导回仓库"正是写入匹配到的那一条（事故依据见 `07` N8） | P1 |
| FR-1.0.22 | **溯源（Provenance）**：纳管 / 分发 / 编辑 / 回滚均记录 `author`（人类或 Agent 标识）+ `commit` + `at`。**记录源为 git commit，不可篡改**；应用层**不提供改写历史或删除记录的接口** —— 这是「人走资产留」的技术基础（`08` §6） | P1 |
| FR-1.0.23 | **折旧度量（Decay）**：三个**独立**维度 —— `staleness`（最后修改距今 + 被引用次数）、`dependency_broken`（声明的依赖与正文引用的文件在当前 Runtime 不可用）、`upstream_divergence`（canonical 与上游已分叉，**依赖 FR-1.0.13，属可裁项**）。**无法判定时必须报 `unknown`，不得默认判为健康** | P3 |
| FR-1.0.24 | **健康度（Health Score）**：由门禁结果 + 折旧三维合成 0–100 分。**是展示与排序依据，不是门禁本身**；必须在 UI 上可下钻到具体规则与折旧维度，禁止只给一个不可解释的数字 | P3 |
| FR-1.0.25 | **适配器路径即数据**：每个 Runtime 的 skill 目录**不得写死在代码常量里**，必须以数据携带 `deploy_dir`（部署根）+ `scan_only_dirs[]`（**只发现、不部署**）+ `fallback_dirs[]`（回退根）+ `verified_at`（验证日期）+ `evidence`（源码 / 实测 / 官方文档）。**部署根 ≠ 发现根，必须分开建模**；**用户必须能覆盖路径**（这是必需功能，不是 nice-to-have）；用户覆盖与内置定义**命名空间隔离**（`builtin:` / `custom:`），"按 key 查定义"的解析顺序必须统一。依据 `07` D1 / N1~N3 | P1 |
| FR-1.0.26 | **写入归属与删除守卫**（一键分发安全的立命之本）：① **替换授权三态** —— `no_clobber`（目标存在且不属于我们 → 拒绝，逐字节保留）/ `recorded`（仅当与部署记录一致时才替换）/ `user_confirmed`（已显式确认），**每个写入调用点必须显式声明被授权销毁什么**；② 任何会删除目标已有内容的写入（`push` / `import` 换源 / `rollback` / 导出落盘）必须**先停下并列出将消失的路径**，由人确认后才动手；③ **无法判断某路径是否会被删时报错，不得猜**；④ **无人值守路径**（启动批量、后台调度、MCP）**一律跳过并保留角标**，绝不替用户做决定；⑤ 导出 / 落盘**目标非空即拒绝**，需覆盖要显式开关。依据 `07` D4 / N15 / N16 | P1 |
| FR-1.0.27 | **部署自证**：任何写入 runtime 目录的操作，完成后必须**回读目标路径**并确认存在、且内容哈希与期望一致，**才允许上报成功**。"我写成功了"与"它在那"是两件事 —— 上游多次出现"同步显示成功、Agent 里什么都没有"。依据 `07` D1 | P1 |
| FR-1.0.28 | **多目标整体拒绝**：一个 Skill 分发到多个 Runtime 时，**任一 binding 非 `SYNCED` 即整体拒绝**并返回冲突明细，**不得挑一个写入、把其余悄悄丢下**。`SYNCED`（内容 hash 相等）是**唯一**可作"可安全覆盖"证明的状态；其余六态一律不可作为依据。无人值守路径同理。依据 `07` D3 | P1 |
| FR-1.0.29 | **仓库协议版本协商**：每个应用层 commit 携带 `Skillos-Protocol: N` trailer；仓库存一份 **sticky 的 `protocol.json`**（**只升不降**，损坏则重写）。**检测"树里有 `protocol.json` 但 commit 无对应 trailer" = 该提交由旧客户端写入** → **拒绝混用**并提示升级。用途：`adapter_version`（FR-1.0.18）只解决**单机内**的模板漂移；**跨客户端**（多台机器 / 不同 skillos 版本）的协议差异必须另有协商机制，否则新旧客户端会互相把对方的状态算错（依据 `06` A4） | P1 |
| FR-1.0.30 | **元数据随仓库版本化，索引可重建**：标签 / Profile 归属 / 启用状态等**协作元数据写入仓库**（`.skillos/` 目录，随 git 版本化）；本地 SQLite **仅为缓存，可随时从仓库重建** —— "SQLite 不进 git，其中的元数据可从 Skill 文件重建"。**重建守卫**：若元数据显示 0 个 Skill 但仓库中存在 Skill 目录 → **拒绝重建**（否则会**清空库**），且必须做成**类型化错误**，使启动流程只在**这一种情况**下自愈（依据 `06` A8） | P1 |
| FR-1.0.31 | **路径键归一化**：判定"两个路径是否同一个"必须用统一路径键 —— 按分隔符**分段**，逐段做 **Unicode NFC 归一化 + case fold**，并校验唯一性。**仅比较大小写不够**：中文、组合字符、全角/半角场景下 `NFC` 差异会让**同一路径被判成两个**（本机 62 个 Skill 全中文名，这是常态不是边角）。依据 `06` A7 | P1 |
| FR-1.0.32 | **Runtime 约定俗成探测**：`scan` 时除扫描已声明的 4 个 builtin + 用户 `custom:` 之外，**额外探测**一份"约定俗成位置白名单"（如 `~/.cursor/skills` / `~/.cline/skills` / `~/.continue/skills` / `~/.windsurf/skills` / `~/.roo/skills` / `~/.aider/skills` / `~/.trae/skills` 等），**命中 `SKILL.md` 的目录**才记为"未纳管 Runtime 候选"上报 Web。**只报告，不写磁盘、不写 binding、不进漂移矩阵**。探测白名单**以数据携带**（不在 `adapters/` 写路径常量），新增 / 删除探测项不改渲染器。依据 `07` D8 / `07` §观察 2 五条之一"可探测" | P3 |
| FR-1.0.33 | **custom Runtime 路径诊断**：用户已声明的 `custom:<key>` Runtime（`FR-1.0.25` 命名空间）在 `scan` 时**检查路径能否命中**（存在性 + 至少一个 `SKILL.md`），命中失败则在 Dashboard 顶部出现「custom 路径未命中」诊断条，让用户编辑路径或删除条目。**只读诊断，不写磁盘**；MCP / 后台批量场景下同样上报（不静默吞掉） | P3 |
| FR-1.0.34 | **显式添加 Runtime（空条目）**：用户在 Web 看到「未纳管 Runtime 候选」或「custom 路径未命中」 → 勾选 / 编辑 → **只创建 `custom:<key>` 空条目**（只记 `key` / `created_at` / `verified_at = null` / `discover_only = true`），**不 import 任何 `SKILL.md`、不写 binding、不写 fallback、不写字段策略**。下一步引导用户去 Runtime 设置页填路径与字段策略并取消 `discover_only` 标志。**触发权完全在用户**（NFR-11.4 无人值守边界）：后台调度 / 批量 / MCP **不得自动调用"加入"** | P3 |

**漂移状态语义**（判定算法见 `04-系统设计.md` §2.1.3）

| 状态 | 含义 | 用户动作 |
|---|---|---|
| `SYNCED` | 磁盘 == 仓库应得内容，且无未纳管资产 | — |
| `SYNCED*` | 内容一致，但含未纳管资产（>阈值文件）| 见徽标，知悉不可追踪 |
| `MISSING` | 仓库有、磁盘无 | push |
| `OUTDATED` | 磁盘未被改过，但仓库已更新 | push |
| `MODIFIED` | 仓库未变，磁盘被手改 | pull 或 push 覆盖 |
| `CONFLICT` | 两边都改过 | 人工四选一（含「两个都保留」） |
| `UNMANAGED` | 磁盘有该目录，但从未纳管（无 binding）| import 纳管，或忽略 |
| `ORPHANED` | 曾被纳管，但 canonical 中已删除 | 清理磁盘副本，或恢复 canonical |

> `SYNCED*` **不是第 8 个状态** —— 它是 `SYNCED` 在「含未纳管资产」时的**显示变体**（`FR-1.0.20`）。状态枚举只有 7 个。

**字段策略基线**（由本机 62 个真实 Skill 实测得出）：

| canonical 字段 | claude | agents | workbuddy | codex |
|---|---|---|---|---|
| `name` | keep | keep | keep | keep |
| `description` | keep | keep | keep | keep |
| `version` | drop | drop | keep | drop |
| `agent_created` | drop | drop | keep | drop |
| `origin` | drop | drop | drop | drop |
| `allowed-tools` | keep | keep | keep | keep |

| FR-3.9 | 元数据存储（Postgres），与本地 SQLite 表结构同构 | P2 |

| FR-3.11 | 顺带托管 Web 控制台静态文件（线上仅需 1–2 个容器） | P2 |
| FR-3.12 | **文件内容不经云端缓存**：云端只保存文件树与哈希（Dashboard 数据源），内容读取一律经 daemon 实时取回 | P2 |

| FR-3.18 | **分发预览契约**：dry-run / 预览接口必须返回与真实执行同构的结果，**含 `held_back_removals`**（将消失的路径 + 位置标注：repo / runtime A / runtime B）。云端不得对预览结果做二次解释或裁剪 | P2 |
| FR-3.19 | **结构化错误信封**：冲突类错误必须返回结构化字段（`conflicts[].path` + 归属证据），且**错误分类与 CLI 同源**（归属冲突 = `TARGET_CONFLICT`；两个库内 Skill 落到同一路径 = `INVALID_INPUT`；目标不可探测 = `IO`）。**拒绝文案只有一处定义**，句子与结构化形式不得各走各的；给出建议前必须先能证明目标存在（"让调用方去 adopt 一份可能根本不存在的内容"比不给建议更糟）。依据 `07` N6 | P2 |

| NFR-3 | **不丢数据** | 分发前必须备份；`CONFLICT` 状态禁止静默覆盖 |

| NFR-6 | **可演示性** | Demo 全线跑本机真实数据，不切换到假数据 |
| NFR-7 | **跨平台** | Windows 优先，兼容 macOS / Linux（约束细化见 `05-跨平台兼容性.md`） |
| NFR-8 | **可测试** | `core` 层为纯逻辑，可不依赖文件系统做单元测试 |
| NFR-9 | **可追溯** | 每次分发、回滚、升级均写入 `sync_records`；**资产身份历史见 FR-1.0.22**（操作记录 ≠ 资产历史，两者不可互相替代） |
| NFR-10 | **门禁不可绕过** | 见下方细化 |
| NFR-11 | **无法证明安全时一个字都不写** | 见下方细化 |
| NFR-12 | **可观测性** | daemon / API / MCP 三入口必须有结构化日志，关键事件必埋（清单见 `04 §6.2.6`）；`op_id` 全栈关联；敏感字段 Scrubber 拦截 |

**NFR-7 细化（P0 级约束，不可妥协 —— 详见 `05-跨平台兼容性.md`）**

| ID | 约束 | 不做的后果 |
|---|---|---|
| NFR-7.1 | git 换行不转换：repo 内 `.gitattributes` 设 `* -text`；所有 git 调用显式传 `-c core.autocrlf=false -c core.quotepath=false` | `git status` 永久显示脏，漂移检测持续误报 |
| NFR-7.2 | CLI 输出强制 UTF-8，中文 Windows（cp936）下不得报 `UnicodeEncodeError` | 中文 skill 名一输出即崩 |
| NFR-7.3 | 文件锁必须跨平台（`filelock`），禁用 `fcntl` / `msvcrt`；**锁必须覆盖 CLI / daemon / MCP 全部写入入口**，而非只在 daemon 内 | Windows 上 import 即崩；多入口并发写同一目录互相覆盖 |
| NFR-7.4 | 路径不得含 Windows 非法字符与保留名；禁止仅大小写不同的同名 Skill | 跨端分发失败、同名互相覆盖 |
| NFR-7.5 | repo 不得位于 OneDrive / iCloud / Dropbox 同步目录内；**检测到则警告并要求显式确认**（`--allow-unsynced-repo` 或配置项），不直接拒绝启动。**注意该开关与冲突策略 `force` 是两回事，命名不得复用** | 哈希随机漂移，写入随机失败；过严的拦截会在演示现场把自己锁死 |
| NFR-7.6 | 本机回环地址统一 `127.0.0.1`，不用 `localhost` | Windows 上 IPv6 优先导致连接被拒 |
| NFR-7.7 | **daemon 必须与 Agent Runtime 处于同一文件系统命名空间**；若 daemon 运行在 WSL 而 Runtime 在 Windows，同步结果对 Agent 不可见 | "同步成功了但 Agent 看不到"，演示现场致命 |
| NFR-7.8 | **路径比较必须用 `canonicalize` 规范化**（大小写 / 8.3 短名 / 软链接差异不得被当成两个不同目录）；**不允许对路径做"整理美化"**（结尾空格与反斜杠在 Unix 上是合法目录名字符，改写会缩到隔壁目录并通过校验）；迁移只在**空目标**上进行，运行时切换 repo 路径**必须要求重启**，且残留物（锁文件、空目录、系统元数据）不得阻挡迁移 | 上游真实事故：仅大小写不同的同一目录被误判为真实迁移 → **永久循环提示**（`07` W3 / W4 / W9） |
| NFR-7.9 | **同步形态双模式**：**拷贝为默认**（跨平台稳定、无权限依赖）；**软链为可选模式**（Linux / macOS 本地开发时"改一处全生效"）。软链模式在 Windows 上权限不足时**降级为 junction**（仅目录）或禁用并隐藏入口。**同一 Runtime 的同一 Skill 不得混用两种模式** | 上游证明两种模式可共存（`06` B6 / `07` W1）；单押一种会丢掉一个真实使用场景 |

**NFR-3 细化（防数据丢失）**

| ID | 约束 |
|---|---|
| NFR-3.1 | 所有文件写操作携带 `base_hash`；不匹配返回 `409 STALE`，**禁止静默覆盖** |
| NFR-3.2 | 分发中断残留（`*.old` / `*.tmp-*`）在启动与 `doctor` 中自动检出并恢复 |
| NFR-3.3 | 三方合并本期只做整文件粒度，不做块内合并（见 OUT-11） |
| NFR-3.4 | **绝不谎报同步**：含未纳管资产的 Skill 不得上报 `SYNCED`（FR-1.0.20）；`adapter_outdated` 不得被吞掉不显示（FR-1.0.19） |
| NFR-3.5 | **base 可精确重建**：任一 binding 的历史 base 必须能由 `installed_commit` + `adapter_version` 唯一定出；禁止用 `installed_version`（版本号）反查 commit |
| NFR-3.6 | **删除前置证明**：删除任何用户可见内容前，必须**证明它仍与部署记录一致**（内容 + 形态：文件 / 目录 / 符号链接），而不是"记录指向它"就够了 |
| NFR-3.7 | **`dry_run` ≡ 真实执行**：预览与落盘共用同一份判据实现（对应 `FR-1.3.7`）。禁止两套实现 —— 上游 `--dry-run` 曾因未执行与真跑相同的归属检查而漏报真实冲突（`07` N17 / #483） |
| NFR-3.8 | **暂存残留必须可自清**：临时 / 暂存目录（`.staged-*` / `*.tmp-*` / `*.old`）必须在替换成功后释放、失败时清理，且**每次提交前都清理一遍**（不能只在冲突路径上清理）—— 否则残留会被 `scan` 收编成一个"新 Skill"（`07` D4 / N16f） |

**NFR-10 细化（质量门禁不可绕过）**

| ID | 约束 | 不做的后果 |
|---|---|---|
| NFR-10.1 | 门禁的 `error` 级结果**必须落库**（`skill_checks`），不得只存在于内存或日志 | 检查"跑过了"但事后无法举证，门禁退化为一次性提示 |
| NFR-10.2 | **MCP 路径不得提供绕过门禁的开关**（`FR-1.3.6`，与 `FR-1.3.5` 同源） | Agent 可自行放行不合格 Skill，治理叙事当场失效 |
| NFR-10.3 | 健康度分数**必须可下钻**到具体规则与折旧维度，禁止只给一个不可解释的数字 | 决策者无法据此行动，分数变成装饰 |
| NFR-10.4 | **置信度优先于覆盖率**：折旧维度无法判定时**必须报 `unknown`**，不得默认判为健康 | 与 NFR-3.4「绝不谎报」同源 —— 一个错误的"健康"比"不知道"危险得多 |
| NFR-10.5 | 门禁判定**只有一份实现**：`check` 命令与 `push` 前置校验复用同一函数 | 两处判定漂移 → CLI 通过而 push 拦截（或反之），用户不再信任门禁 |

**NFR-11 细化（无法证明安全时一个字都不写）**

> 这条是整个产品**数据安全的总纲**，也是「一键分发」能被称为"可信"的唯一依据。上游因此类问题产生过多起真实数据丢失（`07` D3 / D4 / N15）。

| ID | 约束 | 不做的后果 |
|---|---|---|
| NFR-11.1 | **`SYNCED`（内容 hash 相等）是唯一可作"可安全覆盖"证明的状态**；其余六态（`MISSING` / `OUTDATED` / `MODIFIED` / `UNMANAGED` / `ORPHANED` / `CONFLICT`）一律不可作为依据 | "状态亮着 ≠ 内容可丢"，按状态分类做起安全证明会静默删掉用户改动 |
| NFR-11.2 | **多目标分发做前置全量检查**：任一 binding 非 `SYNCED` → 整体拒绝并返回明细（对应 `FR-1.0.28`） | 挑一份写、丢下其余 → 提示成功而改动一字未到，顺着后续提示操作即数据丢失 |
| NFR-11.3 | **会删除内容的写入必须先列出路径再执行**；入口不可探测时报 `IO`，**不许猜**（对应 `FR-1.0.26`） | "一个错误的『什么都不会丢』正是这个机制要防的失败" |
| NFR-11.4 | **无人值守路径永不替用户做决定**：启动批量、后台调度、MCP 遇到需要确认的删除 → 跳过该 Skill 并保留角标，用户手动操作时才展开详情 | 后台静默替用户批准删除，用户无从知晓 |
| NFR-11.5 | **确认绑定到内容**：用户批准的是「这一次修订版 + 这一组精确路径」，集合变化必须**重新询问**，不得拿过期答案动手 | 两次预览之间目标被改动 → 批准的与执行的不是同一件事 |

## 6. 范围边界（明确不做）

| ID | 不做的内容 | 理由 |
|---|---|---|
| OUT-1 | 实时协同编辑（OT / CRDT） | Skill 是文件包不是文档，价值极低、成本极高 |
| OUT-2 | Skill 的**运行时评测与跑分**（真跑 Agent 执行任务并打分） | 需执行环境 + 多次采样 + 基线，成本比静态分析高一个数量级。**必须与 `FR-1.0.23` 折旧度量区分：折旧是「静下来看」（做），跑分是「跑起来测」（不做）** —— 两者常被混为一谈，混了就会把范围撑爆。**叙事上出现的「评测回归」本期即门禁回归**（`FR-1.0.11`，静态、结果落库、可对比历史），**不等于本条的运行时跑分**；对外表述时不得两者混用（口径表见 §0） |
| OUT-3 | Marketplace / 社区分发 | 本期不做 |
| OUT-4 | Agent / Workflow 编排 | 数据模型预留，本期不实现 |
| OUT-5 | Neo4j 知识图谱 | 62 个 Skill 用不上 |
| OUT-6 | 移动端 | 本期不做 |
| OUT-7 | 二进制文件内容 diff | 仅显示"已变更" |
| OUT-8 | diff 与上游对比 | 保留版本间 / 端间即可（首个可砍项） |
| OUT-9 | 语义化工具名转译 | 第一版只做字段白名单 + 透传 |
| OUT-10 | 版本管理的分支功能 | 保留时间轴 + 回滚（首个可砍项） |
| OUT-11 | 冲突解决的**块内逐行合并**（diff3 标记解析 + 前端逐块选择） | 单人场景冲突率极低，为重 UI 不值；本期只做整文件粒度（FR-2.2.6） |

| OUT-15 | `runtime_binding_files`（per-file 基线表） | base 可由 `installed_commit` + `adapter_version` 重渲染得到，`changed_files` 亦可算出，省一张表 |
| OUT-16 | **按需拉取单个 Skill 的窄克隆**（partial clone + sparse-checkout） | 收益是"装一个 Skill 从 15 MB 降到 500 KB"，代价是四个连环坑（必须拷贝缓存不能用 `--local`、sparse 对不存在路径也"成功"、必须断开 promisor 远端关联、否则调用方正常 git 命令会悄悄变成网络往返）。本期 skill 库全在本机，收益为零、风险不为零（`07` N25） |
| OUT-17 | **对象级合并引擎**（以 Skill 为单位的三方合并、pending 冲突跨设备传播、崩溃安全应用序列） | 上游为此做了四轮设计评审（merge-engine v4）。本期冲突走整文件粒度**四选一**（FR-2.2.6）；但其**理念边界要一致**：删除只在对方未动过该 Skill 时才传播、Skill 目录与元数据永远成对移动、应用任一选择前先建安全快照（`07` G7） |

## 8. 优先级与砍单

**不可退让（六项）**：D1 引擎（P1）、D2 Dashboard + 一键分发（P2）、D2 编辑器 + diff（P3）、D1 MCP 模式（P5）、**质量门禁的 `error` 级拦截（FR-1.0.11）**、**一键分发的删除守卫（FR-1.0.26 + FR-1.0.27）**。

> 第 5 项为什么不可退让：它是「资产」定位的技术支点（`08` §3），且**成本极低** —— `checks.py` 在 P1 已有骨架，门禁只是把既有结果接到 `push` 前的判断上，**不新增页面**。
>
> 第 6 项为什么不可退让：**"一键分发"是这个产品的门面，也是唯一能一次删掉用户数据的地方**。没有守卫的分发按钮 = 把演示现场变成一个"点一下就丢文件"的危险品。且它与第 5 项共用同一批前置判定代码，**增量成本几乎为零**。

**砍单顺序**：OUT-10 → OUT-8 → Teams 整体 → 沙盒 → OUT-16 窄克隆 → FR-1.0.12 相似检测 → **FR-1.0.23 的 `upstream_divergence` 维度** → FR-1.0.13 上游跟踪 → **FR-1.0.24 健康度评分退化为「门禁结果计数」** → FR-1.0.25 的 `fallback_dirs[]` 回退链（保 `verified_at` + `evidence`，只留单一路径）→ FR-2.4.8 失效筛选自动清除 → **FR-2.2.6 的「两个都保留」选项**（退化为三选一，**决策前快照不可退** —— 它是数据安全项）→ **FR-1.0.29 协议版本协商**（单机 demo 无对手方，可延后至多客户端场景）。

**P3 唯一不砍单的页面 = Runtime 设置（FR-2.4.10）**（`02` T26 / `03` P3 注释）：溯源 + 诊断 + 配对的承载处，是 Runtime 自动发现（FR-1.0.32~34）的天然归属，与"不新增页面 / tab"硬约束不冲突（它是**唯一例外**）。若 10/12 实在完不成，**优先砍 Settings 的"重新扫描"按钮（保留 GET 走 cache）+ 守护 / 协议 / Token 3 区块的"次要字段"**（设备列表 / 事件 / sticky 单向），**保留 4 区块骨架 + 核心加入 / 诊断 / 撤销**。

> 后几项的降级路径是刻意设计的：**门禁与删除守卫不可砍，但"评分"可退化、"回退链"可退化**。即使健康度只剩 `error / warn` 计数，第 4 层的叙事仍然成立。
