## 0. 两种部署形态

| | 远程部署（演示 / 长期自用） | 本地开发部署 |
|---|---|---|
| 形态 | `docker compose` 两容器 | 三件套各自起进程 |
| 适用 | 评委演示、长期自用、多机共享 | 单开发者改前后端、要断点调云端 |
| 构成 | 容器 A `cloud`（FastAPI + WS Hub + 托管 SPA）<br>容器 B `sandbox`（同一镜像 + `SKILLOS_SANDBOX=1`，daemon 常驻） | ① CLI（`skillos`）<br>② 云端后端（`uvicorn`）<br>③ Web 控制台（`vite dev`）<br>④ daemon（`skillos daemon`） |
| 入口 | `http://<host>:9080` | `http://127.0.0.1:5173` |
| 隔离 | 靠文件系统边界：容器 B 的 root 全在容器内（`FR-2.4.3`） | 靠本机 `~/.skillos`，无隔离 |
| 静态文件 | 容器内构建（`Dockerfile` 多阶段），FastAPI 托管 | vite dev server + 代理 |

> **同一个包，三种运行模式**（`02` §9）：CLI / daemon / MCP 都是 `skillos` 包的入口，容器里跑的就是本机装的那一份代码。

**远程拓扑**（`04` §1.4）

```text
浏览器 ──► 容器 A: cloud  (9080)
              ├── REST /api/*        （元数据 / 协作 / 任务下发）
              ├── WS   /ws/ui         （UI 订阅：漂移变化实时推送）
              ├── WS   /ws/agent      （daemon 出站长连接）
              └── 静态 /              （SPA，见本文 §5）
                   ▲
                   │ daemon 主动出站连 WS（云端不反向连本地）
                   │
      容器 B: sandbox (同一镜像, SKILLOS_SANDBOX=1, SKILLOS_ROOT=/runtime)
              └── skillos daemon ：写操作全落在容器内虚拟目录
```

## 1. 远程部署（docker compose）

适合：演示日评委访问、长期自用、多机协作（**这是大赛要求的方式**）。

### 1.1 前置

- Docker Engine + Compose v2（`docker compose version` 能出结果）
- 生成随机串的工具：`openssl`（或任意 32 字节随机十六进制串）
- 宿主机 **9080** 端口可用

### 1.2 步骤

```sh
cd <repo>                                        # 仓库根（有 compose.yaml 的那一层）
echo "SKILLOS_JWT_SECRET=$(openssl rand -hex 32)" > .env
docker compose up -d --build
docker compose ps                                # cloud 应为 healthy / running
```

`.env` 里的 `SKILLOS_JWT_SECRET` **必须显式设置**：`compose.yaml` 用 `${SKILLOS_JWT_SECRET:?}` 强制校验，缺失直接拒绝启动。理由——不设置时后端会用进程随机值，**每次重启所有登录态失效**，演示现场表现为"突然全部 401"（`04` §4.1）。

> **`SKILLOS_JWT_SECRET` 只存 `.env`，不入 git**（`NFR-2`；`.gitignore` 已含 `.env`）。

### 1.3 验证清单（逐条执行，全绿才算部署成功）

| # | 命令 | 期望 |
|---|---|---|
| 1 | `curl -s http://127.0.0.1:9080/api/health` | `{"ok":true,"data":{"status":"up","sandbox":false},...}` |
| 2 | 浏览器打开 `http://<host>:9080` | 出登录页（SPA 已托管） |
| 3 | 浏览器在登录后**刷新** `/skills/<slug>` | 仍是页面（**不是 404**，见 §5 SPA fallback） |
| 4 | `docker compose exec sandbox skillos doctor` | 10 项自检，**fail 数为 0**（退出码 0） |
| 5 | `docker compose logs -f sandbox` | `install-seed: 出厂态就绪` → `配对成功，token 已保存` → `已连接 ws://cloud:9080/ws/agent` |
| 6 | Web 首页 daemon 徽标 | 在线（`FR-2.1.5`） |
| 7 | 健康矩阵点"一键分发" | 格子上色、状态转 `SYNCED` |
| 8 | 点"重置演示"（沙盒） | `POST /api/sandbox/reset` 成功，现场回到出厂态 |

**第 5 条是核心**：它同时证明"容器 B 起来了"和"容器 A 的 WS 通道是通的"。

### 1.4 访问凭据

沙盒容器首次启动会**注册 demo 用户**（`scripts/sandbox_bootstrap.py` 的 `pair` 子命令，幂等）：

```text
邮箱：demo@skillos.dev
密码：skillos-demo
```

> demo 邮箱**必须用可过 `EmailStr` 校验的域名**（`.local` 是 special-use 保留域，注册直接 422——2026-10-08 修过，改邮箱时别改回 `.local`）。

> 这是**演示凭据**。对外长期开放时改掉它，并在 Web 上撤销不再使用的设备 token（`GET /api/devices` / `DELETE /api/devices/{token_id}`）。

### 1.5 卷与持久化（详见 §3）

| 卷 | 挂载点 | 内容 | 丢了会怎样 |
|---|---|---|---|
| `cloud-data` | `/data`（容器 A） | `cloud.db`（SQLite：用户 / 团队 / 漂移缓存 / `sync_records`） | 协作与缓存丢失；**文件内容本就不在云端**（`FR-3.12`），skill 本体不受影响 |
| `sandbox-data` | `/runtime`（容器 B） | 容器内 home：`repo/`（canonical git）、`skillos.db`、四端 runtime 目录、`.skillos-seed/` | 演示现场丢失；daemon 重启后 `install-seed` 会重新铺出厂态（token 文件随之失效，需重新配对） |

`FR-3.12` / 红线 6：**云端不缓存文件内容**。所以"云端数据库删了"不等于"数据没了"——真值在容器 B 的 git 仓库里，以及每个开发者本机的 `~/.skillos/repo`。

### 1.6 重置演示现场（沙盒专有）

- **Web**：页面上的重置入口 → `POST /api/sandbox/reset`
- **语义**：清空四端 runtime 目录 → 从 `.skillos-seed/` 恢复 → canonical 重建 → 重导 + 全量 push（矩阵归 `SYNCED`）
- **三层可达检查**（缺一层都不可达）：
  1. `engine.is_sandbox`（`SKILLOS_SANDBOX=1`）→ 否则 `NOT_SANDBOX`
  2. daemon 任务白名单的 `sandbox_reset` 分支
  3. 云端路由仅在沙盒部署挂载（非沙盒部署该路径 404）
- **不删内容的安全阀**：runtime root 越出容器根 → `BOUNDARY` 报错，**一个文件都不动**（红线 16：判断不了就报错）
- **seed 缺失** → `SEED_MISSING`：reset ≠ 清空，没有可恢复的预置就拒绝执行

### 1.7 日常运维

```sh
docker compose logs -f cloud            # 云端日志
docker compose restart sandbox          # 只重启沙盒（token 已落盘，重启免配对）
docker compose down                     # 停（卷保留）
docker compose down -v                  # 停并删卷（现场归零，慎用）
git pull && docker compose up -d --build # 升级
```

## 2. 本地开发部署（三件套）

适合：前后端联调、改云端接口、要断点调 daemon。一句话：**本机跑云端（`uvicorn`）+ 本机跑 Web（`vite dev`）+ 本机跑 daemon（`skillos daemon`）**，互不依赖容器。

### 2.1 引擎 CLI

```sh
python -m pip install -e ".[dev]"     # 开发态（可编辑 + pytest/ruff）
# 或长期自用：pipx install .
skillos --help
```

初始化与纳管（首次）：

```sh
skillos init                      # 建 ~/.skillos/repo（canonical git）
skillos scan                      # 扫四端，列出发现
skillos import                    # 纳管进仓库 + 建索引（导入基线）
skillos status                    # 漂移矩阵（CLI 版）
skillos doctor                    # 10 项环境自检
```

`skillos doctor` 的 10 项里，**本地开发最常踩的三项**：仓库在云同步目录（第 1 项，`05` P0-5）、控制台编码（第 2 项，中文描述输出）、git 身份（第 10 项，否则时间轴作者显示 `unknown`）。

### 2.2 云端后端

```sh
# PowerShell
$env:SKILLOS_JWT_SECRET = "dev-secret"       # 固定值：重启不掉登录态
uvicorn skillos.api.asgi:app --reload --reload-dir skillos --port 9080

# bash / zsh
SKILLOS_JWT_SECRET=dev-secret uvicorn skillos.api.asgi:app --reload --reload-dir skillos --port 9080
```

> **`skillos serve` / 直接 `uvicorn` 时 `SKILLOS_JWT_SECRET` 可不设**：env 未设时 `create_app` 首启生成 secret 并持久化到 `<home>/.skillos/jwt_secret`（POSIX 0600），之后每次启动复用 —— 重启不掉登录态。优先级：入参 > env > 持久文件；文件丢失/为空会自动重新生成（最坏结果是重新登录一次）。**生产/容器仍必须显式设置**（§1.2 的 `${VAR:?}` 强制校验不变），不要依赖本机文件。`SKILLOS_ROOT` 沙盒环境的 secret 落在容器目录内，与库、日志同边界。

- **`--reload-dir skillos` 必带**：裸 `--reload` 默认 watch 整个工作目录，`tests/` 跑一遍、仓库根落一个临时 `.py` 都会触发 worker 重启；重启瞬间**所有 WebSocket 被硬重置**，vite 终端刷 `ws proxy socket error: write ECONNABORTED`（排障表有此条），daemon 也被踢一次。限定只看 `skillos/` 包代码即可消除。

- 入口是 `skillos.api.asgi:app`。`skillos.api.main` 只导出 `create_app()` 工厂，**没有模块级 `app`**。
- **`SKILLOS_WEB_DIST` 现在是可选的**：`mount_web()` 会按 `SKILLOS_WEB_DIST` → 仓库 `web/dist`（源码/editable 态）→ 包内 `skillos/web_dist` → 发行包 `runtime/web` 的顺序自动探测（判据是 `index.html` 真实存在）。**源码态以 `web/dist` 优先**：`skillos/web_dist` 是 `pip wheel` 的构建副产物，打包后不再更新，若排在前面会让 `npm run build` 的新产物失效（页面停留在旧版本、assets 哈希不变）。判据是上级目录有无 `pyproject.toml`（有=源码树/editable，无=装机目录）。**前端源码根不参与候选**：目录里有 `package.json` / `vite.config.*` / `src/` 即判定为源码目录并跳过（源码 `web/` 也有 `index.html`，但那是引 `/src/main.tsx` 的 vite 模板，挂上去只会白屏）；显式把 `SKILLOS_WEB_DIST` 指到源码目录会直接报错，不会"看起来挂上了"。本地 vite 开发态（5173）本来就不经 FastAPI 取页面，设不设都不影响；**一旦显式设置，它就是唯一候选**——路径写错不再静默回退，启动日志会写 `web_not_mounted` 并给出原因。
- **源码 Skill 包（`skill/skillos/`）的前端来自包内归档**：这个目录里没有 `web/`、也没有 `runtime/`，所以 `bootstrap.py` 第 5 步按「现成 `web_dist` → 解 `vendor/dist/web-dist.zip` → `npm ci && npm run build`」顺序解析，解包目标是 `<包>/web_dist/`（已 gitignore）。离线机、无 node 也能起单端口；`web-dist.zip` 就是 CI 的 `web-dist` artifact，zip 根即 `index.html` + `assets/`。
- 数据库默认 `sqlite:///./skillos-cloud.db`（相对当前目录）。**生产**用 Postgres（`SKILLOS_DB_URL`），表结构与 SQLite 同构（`02` §9）。
- **wheel 自带前端产物**：`pip install .` 时 `setup.py` 的 `build_py` 钩子把 `web/dist` 拷进 `skillos/web_dist`，再由 `pyproject` 的 `[tool.setuptools.package-data]` 带进 wheel（sdist 侧靠 `MANIFEST.in` 的 `graft`）。所以 `pip install .` 的用户不需要任何环境变量就能拿到控制台；从 sdist 建 wheel 时源码树里没有 `web/dist`，钩子会保留 sdist 自带那份（**不会清空**）。

**一条命令起（不想记 ASGI 入口时）**

```sh
skillos serve                      # 127.0.0.1:9080，自动定位前端产物
skillos serve --port 9081 --open   # 换端口并自动开浏览器
skillos serve --dev                # 不挂 SPA：前端另起 vite(5173)
skillos serve --db-url postgresql+psycopg://... # 覆盖 SKILLOS_DB_URL
```

与 `uvicorn skillos.api.asgi:app` 是同一个应用，只是把「入口路径 + 产物定位 + 打开浏览器」收成一条命令；要在改 `.py` 后自动重启仍用上面的 `uvicorn --reload --reload-dir skillos`（`--reload` 不看目录范围，会把 `tests/` 的动静也算进去）。

### 2.3 Web 控制台

```sh
cd web
npm ci
npm run dev            # http://127.0.0.1:5173
```

vite 把 `/api` 与 `/ws` 代理到 `http://127.0.0.1:9080`（`web/vite.config.ts`），所以**前端代码里没有硬编码后端地址**——API 走相对路径，WS 走 `window.location.host`（同源）。这条约束让"开发态代理"与"线上同源托管"共用同一份前端代码。

接口变更后的固定动作：`npm run gen:api` → 看 TS 报错 → 修调用点（`04` §2.7.1；**禁止手改** `schema.d.ts`）。

### 2.4 daemon（本机数据面）

```sh
# 1) 登录后签发 6 位配对码（也可以是 Web 上的"添加设备"）
python scripts/sandbox_bootstrap.py pair --cloud http://127.0.0.1:9080

# 2) 用配对码启动 daemon（首次）
skillos daemon --cloud ws://127.0.0.1:9080/ws/agent --pair <6位码>

# 3) 之后重启免配对：token 已落盘 ~/.skillos/token
skillos daemon --cloud ws://127.0.0.1:9080/ws/agent
```

- 配对码 TTL 600s，且按 **ip / user 双维度限流**（`FR-3.15`）；连续失败会临时锁定。
- 启动前做环境校验：云同步目录 / WSL 跨 UNC → **直接拒绝启动**（`05` P0-5 / P0-6）。
- daemon 只**出站**连 WS，云端不反向连本地——这是沙盒与本地共用同一条代码路径的前提（`FR-2.4.3`）。

### 2.5 自检（改完代码跑这一组）

```sh
python -m pytest -q                      # 全量：364 passed, 2 skipped
python -m ruff check skillos tests       # lint（CI 同款口径）
python scripts/smoke_web_e2e.py          # 真 HTTP + 真 daemon：配对 → 矩阵 → 分发 → 编辑 → 409 → diff
python scripts/smoke_mcp_stdio.py        # MCP stdio 冒烟
```

`smoke_web_e2e.py` 是**本地部署链路的端到端证明**：它自己起 uvicorn、配对、起 daemon、走一键分发与写链路。部署前跑一遍，比读十遍文档有用。

## 3. 数据存哪

这是评审/排查时被问最多的：服务器里"我的数据"在哪。**两条铁律先行**，后面所有图都从这两条推出：

1. **canonical 仓库 = 事实源**（`FR-1.0.30`；`skillos/store/index_repo.py:3` 明文写"本地 SQLite 是缓存不是事实源"）。
2. **云端不缓存文件内容**（`FR-3.12` / 红线 6）。云端 DB 只有"元数据 + 漂移缓存"，**不是 skill 的副本**。

### 3.1 物理落位（一图看清）

```text
                         [浏览器]
                            │ HTTP / WS  :9080
                            ▼
   ┌──────── 容器 A: cloud ───────────────────────────────────────────┐
   │  /data/cloud.db   SQLite，18 张表（见 §3.3）                    │
   │                ※ 绝不存文件内容（红线 6）                       │
   └─────────────────────────────────────────────────────────────────┘
                ▲                                          ▲
                │ WS /ws/agent                             │ HTTP（签发配对码）
                │ push : drift_changed / file_changed      │
                │ 下发: gate-run / sandbox-reset            │
                │                                          │
   ┌─── 容器 B: sandbox ──────────────┐       ┌─── 你的本机（开发态 §2）─────────┐
   │  SKILLOS_ROOT = /runtime          │       │  ~/.skillos/repo   canonical git  │
   │  ├─ .skillos/                     │       │  ~/.skillos/skillos.db 本地索引  │
   │  │  ├─ repo/      ★事实源         │       │  ~/.skillos/token   daemon 配对  │
   │  │  ├─ skillos.db 本地索引（缓存）│       │  ~/.claude/skills/               │
   │  │  ├─ .skillos-seed/ seed 缓存   │       │  ~/.agents/skills/               │
   │  │  └─ backups/                   │       │  ~/.codex/skills/                │
   │  ├─ .claude/skills/  ◄────────────┼───────┼─ ~/.workbuddy/skills/             │
   │  ├─ .agents/skills/               │       └─────────────────────────────────┘
   │  ├─ .codex/skills/                │
   │  └─ .workbuddy/skills/            │
   └──────────────────────────────────┘
```

### 3.2 拥有方与"删了会怎样"

| 数据 | 物理位置 | 写方 | 是否到对端 | 删了会怎样 |
|---|---|---|---|---|
| **canonical git 仓库** | `.skillos/repo/`（沙盒 = `/runtime/.skillos/repo/`，本机 = `~/.skillos/repo/`） | 入口层（CLI / daemon）：`import` 字节级拷贝；`push` 不修改 | 不主动同步到云（云端不存） | **能**从磁盘四端目录恢复；但若磁盘也丢了 → **不可恢复**。**这是项目里唯一不能丢的真值** |
| **本地 SQLite 索引** | `.skillos/skillos.db` | LocalEngine（`init_env` 自动建） | 不同步 | 下次 `skillos init` 重建，git+磁盘扫描回填（`init_schema` 用 `create_all`，见 §3.5） |
| **沙盒 seed** | `/runtime/.skillos-seed/` | 容器构建期（`Dockerfile`） | 不同步 | 删了 → `reset` 失败（`SEED_MISSING`），需重建镜像 |
| **配对 token** | `.skillos/token`（0600） | daemon（`save_token`） | 不入网（`NFR-2`） | 下次启动要重新 `--pair` |
| **云端 `cloud.db`** | `/data/cloud.db` | 云端 FastAPI | 不反向同步 | 协作与缓存丢失；但 skill 本体不受影响（`FR-3.12`） |
| **四端 runtime 目录** | `~/.claude/skills/` 等 | daemon：distribute；本地引擎：scan | 通过 WS 同步**元数据**到云（不是内容） | 丢 skill 的客户端副本；可用 `skillos push` 重建 |
| **静态备份** | `.skillos/backups/` | 手动 | 不同步 | 独立备份介质，不受容器/本机故障影响 |

### 3.3 云端 18 张表（按职责分类）

定义在 `skillos/store/models.py`，通过 `Base.metadata.create_all` 建表（见 §3.5）。

| 类别 | 表 | 数量 |
|---|---|---|
| **身份与设备** | `User` / `AgentToken` / `PairingCode` / `PairingAttempt` | 4 |
| **协作** | `Team` / `TeamMember` / `ChangeRequest` / `CrComment` | 4 |
| **Skill 元数据** | `Skill` / `SkillVersion` / `SkillFile` / `SkillTag` / `SkillDependency` / `UpstreamSource` | 6 |
| **Runtime 与同步** | `Runtime` / `RuntimeBinding` / `SyncRecord` | 3 |
| **门禁与相似度** | `SkillCheck` / `SkillSimilarity` | 2 |
| **本地独有的** | `SqliteIndexStore` 用同一份模型（`PostgresIndexStore` 继承），所以**云端与本地 schema 同构**（`02` §9 / `04` §3.4） | — |

> 表里**没有**"文件内容"列。`SkillFile` 只存 `path` / `sha256` / `size` —— 哈希不是内容。

### 3.4 重建（删了怎么恢复）

| 丢什么 | 怎么恢复 | 命令 |
|---|---|---|
| 本地 SQLite 索引 | 重建 | `skillos init && skillos scan && skillos import` |
| 云端 `cloud.db` | 重建（用户/token 全失） | `docker compose down -v && docker compose up -d --build` |
| canonical git 仓库 | **不可恢复**（除非有备份） | §1.7 卷要备份 |
| 沙盒 seed 缓存 | 重建镜像 | `docker compose build --no-cache sandbox` |
| 配对 token | 重新配对 | `python scripts/sandbox_bootstrap.py pair --cloud ...` + daemon 重启 |
| 四端 runtime 副本 | 从 canonical 重新分发 | `skillos push`（daemon 模式自动） |

### 3.5 当前实现与"正式口径"的差异（如实记录）

`skillos/store/db.py:32` 文档写"**开发期直接建表；正式口径走 Alembic**"。**当前两端都用 `Base.metadata.create_all`**（`create_app` / `LocalEngine.__init__` 入口处都调 `init_schema`），**Alembic 链路有但未在入口接入**（`data/migrations/env.py` 存在，alembic.ini 在仓库根，但没有任何代码调 `alembic upgrade head`）。

实际影响：

- **开发 / 沙盒 / 单实例生产**没差（`create_all` 对新增列不会自动迁移）
- **生产化前必须补**：在 `create_app` 与 `LocalEngine` 启动时改成 `alembic upgrade head`（先 `alembic stamp head` 把当前 schema 标记为已迁移），否则下次加列直接出 `OperationalError`
- 详见 `07` §3（上游同类项目踩过的 schema 漂移坑）

## 5. Web 托管机制（改这块前必读）

容器 A 用 **FastAPI 同进程**托管 SPA（`skillos/api/web.py`）。三件事必须同时成立，缺一件就是线上故障：

1. **挂载点必须在所有路由之后**。Starlette 的 `Mount("/")` 对空路径会匹配**所有** http / websocket scope，而路由按注册顺序线性匹配 —— 排在 `/ws/*` 之前会直接吞掉 WS 握手，表现为 **daemon 永远连不上、UI 徽标永远离线**（daemon 侧只看到连接被断）。顺序由 `tests/test_web_hosting.py` 守住。
2. **SPA fallback 自己实现**。`StaticFiles(html=True)` 只在请求目录时给 `index.html`；`/skills/:slug` 刷新会 404。回退判据：**无扩展名**且**不以 `api/` / `ws/` 开头** → `index.html`；带扩展名的资源缺失照旧 404（否则构建产物缺失被伪装成 200 白屏）。
3. **路径判断不依赖平台默认行为**。`StaticFiles` 传入的 `path` 已被 `os.path.normpath` 处理 —— Windows 上分隔符变成 `\`，`startswith("api/")` 会**静默失效**，把 `/api/*` 的 404 吞成 HTML。代码统一按 POSIX 归一化后判断（`05` P0-4 的同一条教训）。

验证方式：

```sh
# ① 逻辑层（fixture 产物，8 条断言）：顺序 / SPA 回退 / /api 404 语义 / WS 可达
python -m pytest tests/test_web_hosting.py -q
```

```sh
# ② 真实产物层：用 vite 构建出来的 dist 跑一遍
cd web && npm run build && cd ..

# bash / zsh
SKILLOS_WEB_DIST=web/dist SKILLOS_JWT_SECRET=dev-secret \
  uvicorn skillos.api.asgi:app --port 9080

# PowerShell
$env:SKILLOS_WEB_DIST="web/dist"; $env:SKILLOS_JWT_SECRET="dev-secret"
uvicorn skillos.api.asgi:app --port 9080

# 逐条核对：/（出页面）、/skills/xyz（**不 404**）、/assets/<hash>.js（200）、
#            /assets/nope.js（404）、/api/nope（**JSON 404**）、浏览器 /ws/ui 能连
```

## 6. 排障：症状 → 根因 → 处置

| 症状 | 根因 | 处置 |
|---|---|---|
| `docker compose up` 直接报 `SKILLOS_JWT_SECRET` 相关错误 | 变量未设（compose 用 `${VAR:?}` 强制） | 建 `.env`（§1.2） |
| 容器反复重启，日志 `Attribute "app" not found` | 启动指向了不存在的模块级 `app` | 入口必须是 `skillos.api.asgi:app`（`main.py` 只有 `create_app` 工厂） |
| 容器构建在 `pip install` 处失败 | `pyproject.toml` 的 `readme = CODEBUDDY.md` 而镜像未 COPY 该文件 | `Dockerfile` 已 COPY；若自建镜像需带上（或改 readme 口径） |
| 页面能开，**刷新 `/skills/x` 变 404** | 静态托管缺 SPA fallback | 见 §5 第 2 条 |
| **首页直接 404**（不是白屏） | `mount_web()` 没找到 SPA 产物，整个 `/` 未挂载 | 看启动日志的 `web_not_mounted`：`reason` 会说明是"候选目录都无 index.html"还是"`SKILLOS_WEB_DIST` 指的路径没有 index.html"；跑 `npm run build` 或改对路径 |
| 页面白屏，`/assets/*.js` 404 | `web_dist` 没就位（构建层未拷进镜像） | 检查镜像内 `/app/web_dist/index.html` 是否存在 |
| **daemon 一直连不上**，日志里连接立刻断开 | 静态挂载排在了 `/ws/*` 之前（吞掉 WS） | 见 §5 第 1 条；`pytest tests/test_web_hosting.py` 能立刻暴露 |
| 突然全体 401 | `SKILLOS_JWT_SECRET` 变了（生产漏设 env；本地持久文件 `<home>/.skillos/jwt_secret` 被删/换环境） | 固定 `.env` 值并重启；本地重新登录一次即可 |
| **本地开发首次登录就 401** | 本地 `skillos-cloud.db` 是空库——demo 用户只由沙盒容器/`pair` 脚本注册，本地 `uvicorn` 起的库**没有预置用户** | 页面注册新账号（密码 ≥ 8 位），或跑 `python scripts/sandbox_bootstrap.py pair --cloud http://127.0.0.1:9080` 自动注册 demo 用户后用 `demo@skillos.dev / skillos-demo` 登录 |
| **页面无样式（裸奔）**：布局全散、间距全无 | Tailwind v4 生成间距工具类（`mt-xs` / `p-lg` / `gap-md`…）只认 `@theme` 的 `--spacing-*` 键；只在 `:root` 定义 `--space-*` 时这批类**静默不生成** | 已修（`index.css` 补 `@theme` 块）。再遇到时用 `@tailwindcss/cli -i src/index.css -o t.css` 离线编译后搜 `.mt-xs` 即可定位 |
| 配对失败 `PAIRING_FAILED` | 6 位码过期（TTL 600s）/ 已被消费 | 重新签发配对码 |
| 配对失败 `RATE_LIMITED` | ip / user 维度触发限流（`FR-3.15`） | 等待锁定窗口过去，不要反复重试 |
| CLI 输出中文报 `UnicodeEncodeError` | Windows 控制台编码 | 入口已 `reconfigure(utf-8, errors=replace)`；`doctor` 第 2 项可确认 |
| 时间轴作者显示 `unknown` | git `user.name` 未配置 | `git config --global user.name <可读名字>`；`doctor` 第 10 项 |
| daemon 拒绝启动，日志 `环境校验失败: 仓库位于云同步目录` | `~/.skillos/repo` 落在 OneDrive / iCloud / Dropbox | 换位置（`05` P0-5：云同步会撕裂 git 仓库） |
| 沙盒重置失败 `NOT_SANDBOX` / `SEED_MISSING` / `BOUNDARY` | 三层可达检查之一未满足 / seed 缺失 / runtime root 越界 | 按错误码分别处置；`BOUNDARY` 时**不要手工绕过**，先查 runtime root 配置 |
| 9080 / 5173 端口占用 | 残留进程 | `docker compose down` 或换端口（`uvicorn --port`） |
| dev 终端刷 `[vite] ws proxy socket error: write ECONNABORTED` | vite 的 WS 代理记录套接字中断：`uvicorn --reload` 每次热重载会断掉**所有** WebSocket（含 `/ws/ui`），或浏览器刷新/关标签时恰有广播在写 | **开发态噪音，非故障**：前端 2s 自动重连 + 注册即补状态快照，功能自愈；容器部署无 `--reload`，不会出现。根治：启动命令带 `--reload-dir skillos`（§2.2），别让 tests/ 或仓库根的临时文件触发重载 |
| 云端数据"丢了"但 skill 还在 | 误以为云端存了内容（`FR-3.12`：不存） | 见 §3：内容在容器 B 的 git 仓库里 |
| **Web「最近同步记录」永远为空**，或短暂显示「daemon 离线 · 暂无记录」但徽标在线 | ① daemon 经 `skillos daemon`（CLI 入口）启动时，CLI 的模块级 `setup_logging("cli")` 抢先把 `core/logging.py` 的 `_initialized` 置 True，daemon 自己的 `setup_logging("daemon", home=…)` 被吞 → `~/.skillos/logs/daemon.log` **永不创建**，`logs` 任务恒返回 `missing: true`；② 旧版前端把任何 HTTP 错误都渲染成「daemon 离线」 | 均已修（2026-10-11）：CLI 日志初始化移入 callback 且跳过 `daemon`/`mcp` 子命令；`RecentSync` 离线判定改走 WS 口径（`DaemonStatusContext`）。**升级后需重启 daemon**（旧进程还在跑旧代码），日志文件首次启动自动创建 |
